# Real Dataset Track

Date: 2026-07-10

This track moves the project beyond synthetic 10k drift. The first real
benchmark is a SIFT1M-derived dynamic subset:

```text
source: TexMex SIFT1M
initial vectors: 100,000
inserted vectors: 20,000
deleted vectors: 10,000
final alive vectors: 110,000
queries: 1,000 real SIFT query vectors
dimension: 128
ground truth: exact top-100 over the final alive vectors
```

The drift split is deterministic: inserted vectors are selected from the
high-score region under the mean of the first 16 SIFT dimensions, and deleted
vectors are selected from the low-score region of the initial set. This gives a
real-vector distribution shift while keeping the experiment fully
reproducible.

## Reproduce

Download and prepare data:

```powershell
python experiments\real_datasets.py download-sift --raw-dir data\raw\sift
python experiments\real_datasets.py prepare-sift-dynamic --raw-dir data\raw\sift --out-dir data\sift100k_dynamic --pool-size 200000 --n-initial 100000 --n-insert 20000 --n-delete 10000 --n-query 1000 --gt-k 100 --anchors 128 --batch-size 64
```

Interpretation:

- This real SIFT subset confirms that HNSW is not the right primary target for
  the entry-staleness claim. Its hierarchy is already a powerful entry-routing
  layer, and the base-layer anchor replacement is weaker.
- The same-graph NSG comparison is the cleanest entry-only test so far. On a
  rebuilt final graph, recall differences are intentionally small because the
  topology is already very strong. Dynamic anchors still reduce average
  distance computations versus NSG's entry point at every tested `search_l`,
  and substantially reduce p99 latency in the high-budget `search_l=240` case.
- The no-rebuild dynamic NSG-style experiment is closer to the paper thesis.
  Once inserts/deletes are handled locally instead of by full rebuild, stale
  NSG-style entry pays more distance computations. Dynamic anchors reduce
  average distance computations at every tested `search_l`; at `search_l=240`,
  they reduce p99 latency from `4977 us` to `2948 us` at the same Recall@10
  `0.9997`.
- In the hardest baseline-query bin, dynamic anchors keep the same Recall@10
  as stale NSG entry while reducing p99 latency from `4256 us` to `3194 us`.
  This is the strongest evidence so far for the paper story: entry maintenance
  matters most in dynamic, high-recall, tail-query regimes.
- A learned maintenance scorer was added. The unregularized variant uses
  stale-entry probe costs to bias candidate anchors toward hard-query regions
  and reaches the lowest average distance computations at `search_l=240`
  (`3809.97`), but its p99 latency is worse than density-only dynamic anchors.
  The regularized `learned_balanced` variant warm-starts from 64 density anchors
  and caps inserted-region anchors at 75%. It keeps the same high-recall regime
  while reducing p99 latency from stale NSG entry `4977 us` to `1959 us`, and
  from density-only dynamic anchors `2948 us` to `1959 us`.
- On the hardest baseline-query quartile, `learned_balanced` improves Recall@10
  from `0.9996` to `1.0000`, reduces average distance computations from
  `5065.54` to `4996.48`, and reduces p99 latency from `4256 us` to `2062 us`
  versus the stale NSG entry. This is currently the strongest paper-grade
  evidence for learned, regularized entry-set maintenance.
- The main paper target should remain single-layer or medoid-start graph
  search: NSG/Vamana/DiskANN-style routing, plus GATE/DiskANN++ as close
  entry-overlay baselines.
- The current GATE run is a static centroid-hub adapter, not a paper-faithful
  two-tower GATE run. It is still valuable because it gives a close executable
  static entry-overlay baseline on real vectors.
- The next systems step is to inject dynamic anchors into a Vamana/DiskANN or
  NSG search path directly, so the entry layer changes while the underlying
  optimized graph backend remains fixed.
